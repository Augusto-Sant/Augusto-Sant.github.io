02 Projects

01 Restaurant Assistant

$ how i built it

Customers order by chatting with an agent, and every confirmed order deducts its ingredients from stock. Managers run that stock from a dashboard or by asking the assistant, which waits for approval before it changes anything.

$ stack

  • Python
  • FastAPI
  • LangGraph
  • Postgres
  • Langfuse
  • React
  • Tailwind
  • Three.js

$ what i learned

  • system design A modular monolith with ports and adapters. Each module exposes one small public facade, so the agent never reaches into the domain.
  • agent harness The harness matters more than the prompt: narrow tools, approval gates on risky actions, and traces scored by user feedback.
  • product Chat alone is poor UI. Dish cards, an order timeline and visible tool use are what make the agent easy to trust.

02 Scraper Agent

$ how i built it

You describe the data you want in chat and the agent creates the scraper, defines its columns and schedules it. Playwright loads the page and an LLM extracts the rows into that schema.

$ stack

  • Python
  • FastAPI
  • LangGraph
  • Playwright
  • APScheduler
  • SQLAlchemy
  • Postgres
  • Langfuse
  • React

$ what i learned

  • system design Scraping and chat are separate bounded contexts. Long runs go to background jobs and a scheduler, so the chat never blocks.
  • agent harness The agent gets the same use cases as the API, exposed as tools. Typed schemas keep LLM extraction checkable.
  • product A dashboard beside the chat shows what the agent actually did. Live run status beats a spinner.
